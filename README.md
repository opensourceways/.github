# .github

## Issue 模板文案原则

- Issue Form 是给提单人填写的，用户可见文案要像直接和提单人说话，优先使用“你/请”，不要用“用户”称呼提单人。
- 不要把仓库路由、owner 判断、验收责任等内部流程前置给提单人。提单人只需要描述遇到的问题、发生位置、期望结果和完成后如何确认。
- 避免使用需要解释的内部角色或流程术语，例如“需求接口人”“项目维护人”“验收人角色”。这些信息如有必要，应在后续处理或需求分析阶段补充。
- 结构化字段应服务于提单人表达，而不是为了内部系统收集更多元数据。必填字段只保留提单人一定知道、且对理解需求必要的信息。
- 技术影响范围可以保留为可选项，但要使用提单人更容易理解的语言；如果不确定，应允许不选或选择“不确定”。
